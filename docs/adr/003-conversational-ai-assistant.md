# ADR-003: Conversational AI assistant (persistent chat, real LLM, memory)

- Status: Accepted
- Date: 2026-06-08
- Deciders: JB

## Context

The right-sidebar chat (`ChatAssistantPanel`) was single-turn, not persisted, and
backed by a deterministic templated responder (`chatAssistantService.buildAnswerText`);
`ai-router.ts` only selected a model name and ran a cost gate — no real LLM call exists
anywhere in the app. JB requested a real conversational assistant: tracked conversations,
memory, and the ability to save previous chats and start new ones.

## Decision

1. **Real LLM via Edge Function.** Replies are generated by Anthropic (Claude) through a
   new Supabase Edge Function `ai-chat` that holds `ANTHROPIC_API_KEY`. The browser never
   holds the key (same discipline as `SERPAPI_KEY`, INT-RULE-006). This is the first real
   external LLM call in the app.
2. **Persistence in Supabase.** New tables `chat_conversations`, `chat_messages`,
   `chat_memory` (RLS on, `user_id = auth.uid()`). Each turn is persisted; conversations are
   listable/renamable/deletable; new conversations are created on demand.
3. **Memory = per-conversation history + long-term store.** Thread history is replayed as
   context. Long-term memory (`chat_memory`) is injected into the system prompt and written
   back when the model emits a `MEMORY: <fact>` directive (parsed + deduped client-side),
   keeping cost to one LLM call per turn. A manual save path is also supported.
4. **Routing + cost unchanged.** Calls go through `routeAiTask('general_qa')` →
   "Claude Sonnet 4.6" (mapped to `claude-sonnet-4-6` at the Edge boundary), the $75/mo cap
   gates dispatch (deferred message when capped), and `logAiUsage` records real tokens
   (AI-RULE-002).
5. **Feature location.** New code lives under `src/features/ai-agent/` per the source-directory
   contract; the old single-turn `ChatAssistantPanel`/`chatAssistantService` context helpers are
   reused (e.g. `getPipelineContextSummary`, `classifyChatIntent`).

## Consequences

- Real token spend now accrues against the cap (previously $0 — everything was deterministic).
- `ANTHROPIC_API_KEY` must be provisioned as a Supabase secret; the migration must be applied
  and `pnpm db:gen-types` run (then re-derive `src/features/ai-agent/types.ts` from `Database`).
- The model-routing matrix still pins display names; the display→API-id map lives at the Edge
  boundary. Pinned "Opus 4.6" predates the current Opus id and resolves to the latest Opus.
- Streaming and Supabase Realtime are deferred (v1 reloads messages after each turn).
